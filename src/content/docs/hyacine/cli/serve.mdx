title: hyc serve

`hyc serve` 启动一个本地 REST API 服务器，供 [HyC 官方控制台](https://hyc.kaitaku.xyz/) 或自定义前端调用。服务器提供文章管理、主题配置、AI 功能等完整的 REST API。

## 用法

```bash
hyc serve [选项]
```

## 选项

| 选项 | 默认值 | 说明 |
| :--- | :--- | :--- |
| `-p, --port <端口>` | `3789` | API 服务端口号 |
| `--setup` | `false` | 启用项目初始化模式（用于交互式安装向导） |
| `--unsafe` | `false` | 启用不安全 API（调试用） |
| `--bypass-origin-check` | `false` | 跳过 Origin 白名单检查 |
| `--bypass-host-check` | `false` | 跳过 Host 白名单检查 |

## 三种运行模式

| 模式 | 标志 | 说明 |
| :--- | :--- | :--- |
| **normal** | （默认） | 标准模式，需要已初始化的项目 |
| **setup** | `--setup` | 初始化模式，用于交互式安装向导，要求工作目录中没有 `package.json` |
| **unsafe** | `--unsafe` | 调试模式，启用所有 API 端点 |

:::caution
`--setup` 和 `--unsafe` 不能同时使用。
:::

## 安全机制

`hyc serve` 默认启用了多层安全保护：

1. **认证码**：每次启动生成 16 位随机认证码，所有 API 请求需携带 `Authorization` 头
2. **Origin 检查**：仅允许 HyC 官方控制台的白名单域名访问
3. **Host 检查**：仅接受本地主机请求
4. **速率限制**：每 IP 每分钟最多 120 次请求
5. **CORS**：跨域请求受控

## 与 HyC 控制台配合使用

1. 在项目目录运行 `hyc serve`
2. 记录输出的 16 位认证码
3. 打开浏览器访问 [https://hyc.kaitaku.xyz/](https://hyc.kaitaku.xyz/)
4. 在控制台输入认证码
5. 开始使用可视化的文章管理、主题配置等功能

## 常见问题

### Q: 为什么需要认证码？

认证码确保只有你本人（知道认证码的人）可以操作你的项目。认证码在每次 `hyc serve` 启动时随机生成，不会存储在文件中。

### Q: 可以在远程服务器上运行 serve 吗？

理论上可以，但需要注意：
- 默认 Host 检查只允许 `127.0.0.1` 和 `localhost`
- 需要 `--bypass-host-check` 和 `--bypass-origin-check` 选项
- 认证码通过明文传输，建议使用 SSH 隧道或 VPN 保护安全

### Q: serve 启动失败，端口被占用？

使用 `-p` 选项指定其他端口：

```bash
hyc serve -p 3790
```
